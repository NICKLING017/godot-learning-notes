# 小地图系统

小地图的目标是把程序化生成的房间网格转换成玩家能读懂的 UI 状态：未发现、已发现、当前房间、已清理、锁定。它是 Arena 房间状态的可视化，不应该反过来控制关卡逻辑。

## 系统组成

| 模块 | 职责 |
|------|------|
| `Arena` | 生成房间后提供网格数据，并在玩家进入房间时同步状态 |
| `MapController` | 根据房间坐标创建和更新小地图格子 |
| `MapCell` | 渲染单个房间的状态 |
| `EventBus` | 广播房间锁定、清理、进入等事件 |

## 状态设计

| 状态 | 含义 | UI 表现 |
|------|------|---------|
| `HIDDEN` | 玩家尚未发现 | 隐藏或透明 |
| `VISITED` | 已发现但不是当前房间 | 灰色半透明 |
| `CURRENT` | 玩家所在房间 | 高亮 |
| `CLEARED` | 已清理房间 | 绿色 |
| `LOCKED` | 战斗锁定房间 | 红色 |

## 关键数据结构

Arena 需要维护从房间实例到坐标的反向映射：

```gdscript
var room_to_coordinate: Dictionary[LevelRoom, Vector2i] = {}
```

这样当 `EventBus.on_player_room_entered(room)` 触发时，Arena 可以立刻找到对应坐标并通知小地图更新。

## 学到的 Godot 点

- UI 不应该重新推导关卡拓扑，而应该消费 Arena 已经生成好的 `grid` 数据。
- `Vector2i` 很适合作为房间网格坐标，能稳定映射到小地图单元格。
- 用枚举表达 UI 状态，比散落的颜色判断更容易维护。
- 小地图状态更新适合通过事件驱动，避免每帧轮询房间状态。

## 后续优化

- 给 `MapCell` 增加方向连接线，让小地图能显示走廊连通关系。
- 当前房间可以使用轻微动画或描边，不只依赖颜色区分。
- 战斗结束时由 `on_room_cleared(coordinate)` 统一更新小地图和房间门状态。
