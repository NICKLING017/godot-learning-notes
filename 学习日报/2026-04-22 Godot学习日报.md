- **字体与主题资源**：通过 `.tres` 主题资源集中管理字体、描边、阴影、价格文本样式和提示面板样式，比在多个场景里分散调样式更便于统一 UI 观感。
- **2D 光照表现**：为玩家、敌人、子弹、道具和商店物品添加点光源，可以让像素风场景更有层次，也能把交互物和危险物从背景里区分出来。
- **自定义 Resource 数据驱动**：`WeaponData` 增加 `magazine_size`，说明武器差异应优先沉淀到数据资源，而不是写死在玩家或武器脚本里。
- **弹药状态建模**：远程武器拆成“弹匣内弹药”和“储备弹药”，让射击、拾取弹药、商店补给、换弹这几类行为有了更清晰的状态边界。
- **输入动作与交互状态**：新增 `reload` 行为后，玩家脚本需要同时处理主动按键、弹匣打空自动装填、弹药不足等状态转换。
- **Control 节点交互动画**：`CardTiltEffect` 通过鼠标位置驱动卡片倾斜，适合封装成可复用组件，而不是把视觉反馈直接塞进主菜单逻辑。
- **本地化键维护**：主菜单和商店提示新增文案后，同步更新 `localization.csv` 与生成的翻译资源，能避免 UI 写死中文或英文。
- **场景焦点管理**：商店物品引入“购买焦点”，本质是解决多个 Area/Control 同时可交互时的优先级问题。

## 代码或场景改动带来的理解

弹匣系统的关键不是只增加一个 `magazine_size` 字段，而是重新划清职责：武器资源负责声明容量和基础属性，玩家负责持有当前弹匣与储备弹药状态，UI 和商店只消费这些状态并反馈给玩家。这样后续要扩展“快速弹匣”“无限弹药房间”“装填速度词条”时，不必推翻现有结构。

商店购买焦点的改动说明，交互提示不能只依赖“玩家是否在某个商品范围内”。当多个商品重叠或距离接近时，需要一个明确的当前目标，否则会出现提示混乱、购买对象不确定的问题。用焦点机制先选定对象，再显示提示和处理输入，是更稳定的交互模型。

主菜单双卡片与倾斜效果体现了 UI 组件化的价值：卡片倾斜是一种可复用视觉行为，单独做成脚本后，主菜单只需要管理卡片切换和状态，不需要关心鼠标坐标如何转换成旋转角度。

## 遇到的问题与解决方式

- **中文字体显示与 UI 风格不统一**：通过引入 Ark Pixel 中文像素字体，并在主题资源里统一字体、描边与阴影，解决字体风格和中文显示质量问题。
- **近战武器不应显示弹药 UI**：移除近战武器上的 `max_ammo` 配置，让弹药 UI 的显示逻辑可以根据武器类型和弹药数据自然区分。
- **商店提示与购买对象容易冲突**：通过购买焦点机制限制同一房间只有一个商品处于可交互状态，并把提示文本从“按 E 购买”简化为“购买”，让输入提示与当前焦点解耦。
- **弹药恢复规则容易含混**：把恢复逻辑改为优先补充弹匣，再补充储备弹药，使拾取弹药和商店补给的结果更符合玩家预期。
